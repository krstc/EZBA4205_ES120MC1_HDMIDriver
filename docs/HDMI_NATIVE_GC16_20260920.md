# ES120MC1 原生 GC16 编译候选版（2026-09-20）

本版用于验证原生 16 灰阶的对比度和残影，尚未进行实屏验收。前一版实际使用二值 DU5 波形，通过空间点阵模拟灰阶；本版保留每个像素的 4 位新旧灰阶，执行完整 GC16。关闭蓝噪声、Bayer 和误差扩散，提示文字也不再使用黑白点阵。

## 分辨率和输入

| 项目 | 本版数值 |
|---|---|
| HDMI、DDR 有效图像、面板 | 2560 × 1600 |
| 水平前肩 / 同步 / 后肩 | 48 / 32 / 80 像素 |
| 水平总长 | 2720 像素 |
| 垂直前肩 / 同步 / 后肩 | 3 / 6 / 37 行 |
| 垂直总长 | 1646 行 |
| HDMI 像素时钟 | 111.93 MHz |
| 输入刷新率 | 111930000 / (2720 × 1646) = 25.000447 Hz |
| EDID 产品标识 / 校验字节 | EPD0133 / 0x5C |
| EDID DTD 时钟字节 54、55 | 0xB9、0x2B |
| ADV7611 TMDS 接受范围 | 110～114 MHz，同时要求有效 DE 几何和 VS 频率 |

删除了旧版 2650 像素活动区和左右各裁剪 45 像素的配置。Vivado 顶层 generic 明确固定 HDMI_H、FRAME_H、EPD_H、MAX_H 为 2560，各高度为 1600。保留已验证的 ADV7611 I2C、EDID 装载/校验、HDMI 引脚和时钟切换流程。新的产品标识让 Windows 能区分旧 EDID 实例；实际主机/扩展坞是否读到新块仍需连接后确认。

输入沿用已配置的 studio-range 亮度展开：16 以下为黑、235 以上为白，中间使用已有的 149/128 定点比例。随后按最近值量化成 0～15，不经过原二值点阵路径的 1.5 倍对比度曲线。黑白端点分别是 0 和 15；提示文字为 11/15，约 73% 白亮度，接近此前要求的 75% 灰色。

## GC16 来源与转换

本地参考目录：`datasheet/src/ES120MC1-EpdiyV7/lib/epdiy2/src/`。

`displays.c` 中 ES120MC1 明确选择 `epdiy_ED047TC1` 默认波形。采用该表的 MODE_GC16（模式 2）、温度区间 20～30°C，共 30 个阶段。本版没有将其他屏幕的表凭名称套入 ES120：使用的是用户提供的 ES120 例程实际选用的同一张表。但它不是新测得的 ES120 专用温度标定表，实际面板光学效果需要验证。

`tests/generate_es120_gc16.py` 解析 `waveforms/epdiy_ED047TC1.h` 的 C 初始化数组，按 `output_common/lut.c` 相同次序解包。C 数组结构是 `[phase][target][old/4]`，每个字节从高位到低位依次放四个旧灰阶的 2 位驱动码。

```text
packed = table[phase][target][previous / 4]
code = (packed >> (6 - 2 * (previous % 4))) & 3
ROM address = (phase << 8) | (target << 4) | previous
00 = 中性、不驱动；01 = 驱黑；10 = 驱白；11 不输出到面板
```

源表 SHA256：`40ff2bcce909678fbb870039a7f72537daf0f3446e4c82342d37ef0abaef3e84`。
生成的 8192 项 ROM 包含 7680 项 GC16 数据及两阶段零填充；完整驱动码字节序列 SHA256：`d71d69829762d29cdf950eaf571cce6cc225478f362eb9270fe1661989e125a9`。

注意：参考头文件带有 `phase_times`，但该项目 ESP32-S3 LCD 输出后端的 `lcd_do_update()` 使用固定 LCD 扫描；它没有像另一个 I2S 后端那样用这些值改变逐行驱动时长。因此本版保留表的全部阶段和顺序，每阶段执行一次已验证的完整面板扫描，不把这些数值错误解释成毫秒重复次数。原表中的时间元数据仍保留在源文件中，未声称 FPGA 与 ESP32 外部引脚在所有时间细节上完全相同。

普通更新：30 个 GC16 阶段，随后 2 个中性扫描。同灰阶像素输出 00，防止静态区域被无意义重复驱动。每个目标图像在完整更新结束前不可被新 HDMI 帧替换。

## 缓冲与局部消影

| 缓冲区 | 起始地址 | 预留大小 | 数据格式 |
|---|---|---|---|
| 新旧转换 0 | 0x0E800000 | 4 MiB | 每像素 `{目标灰阶[3:0],旧灰阶[3:0]}` |
| 新旧转换 1 | 0x0EC00000 | 4 MiB | 同上 |
| 原纹理区 | 0x0F100000 | 4 MiB | 本版不从此区读取抖动纹理 |
| 灰阶帧 0 | 0x0F500000 | 4 MiB | 每像素一个字节，灰阶 nibble 重复 |
| 灰阶帧 1 | 0x0F900000 | 4 MiB | 同上 |

每帧实际使用 4,096,000 字节。清 DDR 时同时将两份旧灰阶和两份转换缓冲初始化为白色/白到白。已检查沿用的 ARM 应用 ELF 的实际装载段，不与新增 0x0E800000～0x0F000000 区间重叠。

采集完成必须同时满足灰阶帧写入完成和最后一行转换数据写入完成。GC16 输出结束后才允许采集下一帧，这既保证旧状态一致，也避免 50 MHz、64 位 FDMA 同时承担高带宽采集与完整扫描。输出端每周期并行查询 8 个像素，拼接顺序与原串行器一致。

行请求独立排队，不会因前一行 DDR 事务尚未结束而丢失。增强测试每 41 行插入一次 150 个系统时钟周期的响应等待，使事务跨过下一次行请求。未排队版本能稳定复现第 82 行错位；修正后在相同条件下逐像素通过全部 1600 行。

保留 32×16 像素的区域历史图，共 8000 个区域。比较完整 4 位灰阶，包括 MSB 不变的深灰到深灰变化。运动停止后对受影响区域执行一次白色恢复：10 个刷白扫描、2 个中性扫描，再从白色状态执行全部 30 阶段 GC16 重绘目标，最后 2 个中性扫描。共 44 扫描。恢复覆盖受影响区域内的黑色、中间灰色和白色，避免只修复 Word 白底、遗漏两侧深色背景。

不设置静止画面的周期性全屏黑白刷新。运动后的区域恢复只消费一次历史；M18 手动清屏及清屏后的 DDR 白色状态重建继续保留。HDMI 信号在正在执行的恢复期间丢失，也不会中途改变该恢复波形。

## 上电清屏

取消开机竖条，进行 3 轮完整清理，每轮是 W10 → B10 → W10 → N2，最后回白。每轮从启动算起至少 3 秒；完整波形执行完后，剩余时间输出中性状态让面板稳定，三轮合计至少 9 秒。没有把高压驱黑或驱白码持续保持 3 秒。

三轮清理完成后进入 NO SIGNAL / HDMI 检测。保留 HDMI IN、接收信息两段提示及随后真实 HDMI 内容的切换。运行时手动清理不额外引入每轮 3 秒的开机等待。

## 面板时序与速度边界

本版保留此前已实屏验证的 `clock_pll_es120mc1.v`、`frame_ctrl_es120mc1.v`、`data_mgr.v`。模式为 16 位总线、每个 SDCK 传 8 像素的单沿采样；数据在下降沿更新，为上升沿采样提供建立/保持时间。没有改成双沿采样。

| 参数 | 数值 |
|---|---|
| LSL / LBL / LDL / LEL | 14 / 10 / 320 / 18 SDCK |
| GDCK_STA / LGONL | 4 / 264 SDCK |
| FSL / FBL / FDL / FEL | 1 / 4 / 1600 / 18 行 |
| 每行总 SDCK / 每帧总行 | 362 / 1623 |
| SDCK | 44.067796610 MHz |
| 单次完整扫描 | 约 13.3323 ms，约 75.0057 Hz |
| 普通 GC16 32 扫描 | 约 426.6 ms，波形上限约 2.34 次完整更新/秒 |
| 区域恢复 44 扫描 | 约 586.6 ms |

HDMI 的 25 Hz 是输入频率。原生 GC16 需要多次面板扫描，不能据此声称 25 fps。加入等待输入帧和 DDR 采集后，本版完整图像更新预计约 2 fps；实际需实测。本版用于优先验证无点阵的原生灰阶质量，视频流畅度会低于此前 DU5。
