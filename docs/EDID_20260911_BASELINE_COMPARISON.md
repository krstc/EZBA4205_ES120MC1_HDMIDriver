# HDMI 25 Hz 兼容性测试版：与 8 月 18 日基线的核对

## 结论和边界

本次按用户提供的《EDID修改与验证基线.md》和当时会话记录恢复 HDMI 的
**2650 x 1600 @ 25 Hz** 模式，生成独立测试候选，不覆盖已确认屏幕显示正常的固件。
这是恢复历史成功输入模式的兼容性测试，尚未证明 Type-C 扩展坞会按本次 EDID 输出。

面板、DDR 帧缓冲仍然是 **2560 x 1600**。输入左右各裁去 45 列，保留输入列
45..2604；不缩放、不修改行序和面板 LUT。电脑桌面两侧各有 45 列不可见，这是本版
明确的测试限制，不应作为原生 2560 x 1600 无裁剪问题已解决的依据。

## 历史记录的实际含义

- 本地 2026-08-18 00:28 用户确认 25 Hz 出现，00:32 输出基线文档。
- 当时成功的是 2650 x 1600，不是面板原生 2560 x 1600。
- 当时 DTD：`2B 2D 5A A0 A0 40 2E 60 30 80 36 00 03 A2 10 00 00 1E`。
- 源码产品号 0128，Windows 缓存产品号 0129；源码扩展数 0，Windows 扩展数 1。
  所以历史成功证明了 25 Hz 模式能枚举，不能证明全部 EDID 字节原样穿过链路。
- 历史 DTD 的水平前肩 48、同步 128、消隐 160，计算后肩为 -16，不合法。
  本次保留当前合法的 48/32/80，不复制该字段错误。
- 旧文档说 ADV7611 不重算校验和，这不符合 UG-180：使能内部 EDID 时，芯片会
  重算各块校验和。仍应主动写入正确校验和并回读，而非依赖错误常量。

校验行为依据 [ADI UG-180 第 31..33 页](https://www.analog.com/media/en/technical-documentation/user-guides/ug-180.pdf)。
旧文档作为历史记录保留；其中 `0x50` 不适用于本次 EDID，也不能代替按字节重算。

## 本轮观察到的差异

上一版 `20260910_white_hdmi25` 预期 128 字节 EDID：
产品号 0130、2560 x 1600、111.93 MHz、25.000447 Hz、扩展数 0。

本轮 HDMI 断开前，活动 WMI 实例 `DISPLAY\EPD0131\4&fb571d8&0&UID4165_0`
读取到的新名称仍是 `ES120MC1-25Hz`，但像素时钟变成 268.50 MHz，刷新率为
59.971589 Hz，且带一个额外 CTA 块。与预期基本块只有以下五处不同：

| 偏移 | 预期 | WMI 所见 | 含义 |
| --- | --- | --- | --- |
| 0x0A | 30 | 31 | 产品号低字节 |
| 0x36 | B9 | E2 | DTD 像素时钟低字节 |
| 0x37 | 2B | 68 | DTD 像素时钟高字节 |
| 0x7E | 00 | 01 | 扩展块数 |
| 0x7F | 5F | F7 | 基本块校验和 |

额外 CTA 块包含 1080p60；其内容也出现在历史 0129 实例中。活动实例注册表与 WMI
一致，没有该实例的 `EDID_OVERRIDE` 子键。以上是电脑驱动所见 EDID，**不是直接
读 ADV7611 RAM**，不能仅凭这些数据认定是扩展坞、驱动或者板上哪一层改写。
历史缓存对照另存于 `build/edid_registry_comparison_20260911.json`，已注明不是实时读数。

之后用户明确 HDMI 未连接。本轮没有取得可靠的在线 ILA 数据，也未烧写或复位板卡。

## 本次修改

| 项目 | 新候选 |
| --- | --- |
| HDMI 输入有效区 | 2650 x 1600 |
| HDMI 像素时钟 | 115.63 MHz |
| 水平：有效/前肩/同步/后肩 | 2650 / 48 / 32 / 80 |
| 垂直：有效/前肩/同步/后肩 | 1600 / 3 / 6 / 37 |
| 总计 | 2810 x 1646 |
| 实际刷新率 | 115630000 / 2810 / 1646 = 24.999676 Hz |
| EDID 产品号 | 0132 |
| EDID 名称 | ES120MC1-25Hz |
| 基本块校验字节 | 8F |
| 扩展块数 | 0 |
| 接收频率门限 | 113..118 MHz，且 VS 为 24..26 Hz |
| 原始 DE 尺寸门限 | 必须 2650 x 1600，裁剪前检查 |
| 写入 DDR / 面板尺寸 | 2560 x 1600，中心裁剪 |

新 DTD：`2B 2D 5A A0 A0 40 2E 60 30 20 36 00 03 A2 10 00 00 1E`。

修改仅涉及 `config_reg_es120mc1.v`、顶层 HDMI 接线及新抽出的
`hdmi_input_es120mc1.v` 输入寄存/裁剪模块。恢复 2650 时不能只改 EDID：旧的
2560 宽度检测和最高 115 MHz 门限都会拒绝 2650 / 115.63 MHz 输入。

ADV7611 管理状态机保持上一版完整 128 字节回读校验，成功后才发布 HPD。
原来的预配置、1 秒 HPD 低保持、尾序 `64 74 01 -> 98 20 F0 -> 68 6C A2`
均不变。HDMI 仍连接采集、DDR、DU 转换和面板链路，没有改回本地测试专用模式。

## 验证范围

- EDID 仿真从实际配置表导出 `edid.bin`，验证 I2C 打包、校验和、DTD、合法消隐和 25 Hz。
- HDMI 输入仿真验证真实 2650 列进入、2560 列输出、左右 45 列边界、逐像素顺序，
  并拒绝 2651/2560/1920 列输入和错误行数。
- 采集仿真使用约 115.63 MHz 像素时钟，覆盖异步时钟、DMA 停顿及像素打包。
- 接收状态机仿真覆盖完整回读后发布、校验失败、NACK、未就绪状态和 TMDS 读数。
- 新增物理 SCL/SDA I2C 从机模型，验证全部 256 种字节值、重复起始读和 NACK。
  该测试通过，没有因此认定实际硬件 I2C 或扩展坞已通过。
- 同时重跑原有启动、字体/竖条、波形及完整 1600 行传输回归。
- 综合、布局布线、时序及测试日志随候选一同保存；具体完成结果见发布目录 README。

## 配合测试

1. 用户确认后才烧录新候选，NAND 启动；本轮只编译，不自动烧写。
2. 保持上一版正常的上电清屏、5 秒竖条和居中提示流程。
3. 接入 HDMI；必要时将 Type-C 扩展坞从电脑端拔下重接，触发重新枚举。
4. 首先检查电脑是否提供 **2650 x 1600 / 25 Hz**，不是只看显示器名称。
5. 用当前诊断脚本读取活动 EDID 的全部块，保留逐字节差异：

```powershell
cd C:/Users/kongrong/Desktop/fpga/eink
./diagnostics/read_windows_edid.ps1 `
  -ExpectedFile ./build/releases/20260911_hdmi_compat25/edid.bin `
  -OutputFile ./build/edid_after_compat25.json
```

如果仍为 59.97 Hz，不继续改屏幕时序。保持 HDMI 连接、NAND 启动和供电，接 JTAG
仅采集 ILA，核对 EDID 校验结果、TMDS 读数、帧率、原始尺寸及采集选择。
发布目录内 `.bit` 必须配合同目录 `.ltx` 使用。

如果 25 Hz 已出现但仍 NO SIGNAL，也不能简单移除保护门限：应先查哪一项资格检测
未通过。Windows 回读正确及实际 HDMI 图像显示正确，两项均完成后才能确认硬件修复。
