# ES120MC1 空间抖动 + DU5 候选版本（2026-09-21）

本版本根据上一版原生 GC16 的实测问题改为“空间抖动输入、二值 DU5 输出”。活动 HDMI 路径不再调用 GC16；GC16 表仍保留在工程中供回归和后续静态模式使用，但顶层 `USE_NATIVE_GC16=0`，状态机也不会把静止帧提升到 GC16。

## 这次的刷新路径

- HDMI 输入仍为 `2560x1600 @ 25 Hz`，EDID、ADV7611 配置、接收时序和 DDR 地址沿用已验证版本。
- 8 bit HDMI 灰度先做 studio range 16..235 到 0..255 的展开，再做中间调对比度映射。
- 每个像素使用完整 16x16 蓝噪声 rank tile 做阈值比较，输出只有 `00` 或 `ff`。与原来的 4x4 单元相比，16x16 tile 不会把动画大片区域组织成明显的 4x4 方块。
- 每个像素保留 16 bit 更新状态。黑白变化用 DU5，三次面板扫描组成一个数据包；反向时只补偿已经施加的剂量，所以白色鼠标离开黑底、黑色工具栏变白时不会把未完成的旧方向继续刷下去。
- 采集和面板显示继续重叠，缓冲区只有在完整帧和显示事务都完成后才复用。
- HDMI IN 和 TMDS 信息提示仍在显示完成后各保持约 2 秒；这个计时由 `HDMI_STAGE_CYCLES = 50 MHz * 2 s` 控制。

## 为什么 Word 快速滚动有效

它依赖四个条件同时成立：逐像素保存上一帧的实际驱动进度；变化区域优先使用 DU5 短波形；新帧采集与上一帧显示并行；面板每包接收三个连续扫描字段。这样文字滚动时只给发生变化的像素施加有限剂量，未变化的白色工具栏保持 `00` 空驱动，不会因为整帧重新开始而变黑。当前版本把同一套反向补偿也用于鼠标和动画目标变化。

## 与上一版的取舍

空间抖动的灰度由屏幕空间的黑白像素密度表达，不是原生 16 灰阶波形。它能避免 GC16 长波形造成的低帧率和灰雾，但快速运动时仍会有电子纸本身的残影；连续运行后的整屏清理仍应使用 M18，不能把 25 Hz HDMI 输入等同为面板每个像素的 25 Hz 完整灰阶刷新。

## 构建和验证

候选输出目录为 `eink/build/hdmi_spatial_du5_20260921`。回归覆盖蓝噪声计数、黑白鼠标式反向、原有 DU5/GC16 单元回归、状态保持、2560x1600 数据路径、EDID/I2C/接收器和 DDR/ELF 地址检查。此轮只编译、仿真和生成候选包，不自动连接 JTAG 或烧写 NAND。
