## 3. 面板扫描与 HDMI 是不同的时钟域

| 项目 | 当前配置 | 含义 |
|---|---:|---|
| FPGA 系统时钟 | 50 MHz | 控制状态机、DMA 控制、5 秒计时 |
| 面板 SDCK / XCL | 14.6892655367 MHz | 单次输送 8 个像素的驱动码 |
| 面板完整扫描率 | 约 25.001899 Hz | 一轮扫描 1600 个有效行 |
| 一次 DU 图像更新 | 5 次完整扫描 | 约 200 ms，另加采集、存储及调度时间 |
| HDMI 像素时钟 | 111.93 MHz | 一拍一个输入灰度像素 |
| HDMI 输入帧率 | 25.000447 Hz | EDID 首选且唯一明确声明的输入模式 |

因此，HDMI 25 Hz 不等于墨水屏每秒完成 25 次五阶段 DU 图像更新。本版本按完整输入帧捕获并显示，不保证逐帧显示全部 25 帧输入，也不进行 16 级灰度波形更新。

### 4.2 管脚信号与边沿

| RTL 输出 | 面板信号 | 行为 |
|---|---|---|
| EPD_XCL | SDCK / CKH | 连续源时钟 |
| EPD_DOUT[15:0] | SDD[15:0] | 8 个 2-bit 驱动码 |
| EPD_XSTL | SPH | 源数据窗口内低有效 |
| EPD_XLE | LEH | 锁存上一行移入的数据 |
| EPD_SKV | CKV | 栅极行时钟 |
| EPD_SPV | SPV | 帧起始脉冲，低有效 |
| epd_dir | 扫描方向控制 | 固定为 1，保留已验证接线方向 |

面板按 **SDCK 上升沿单沿采样**。FPGA 在 SDCK 下降沿更新数据及控制，为下一个上升沿提供约半周期的建立时间。不是 DDR 双沿送数；不要再增加一套上升沿/下降沿像素序列。

RTL 中 `EPD_WID=16`，每个 SDCK 传 16 bit，即 8 个 2-bit 像素，`LDL=2560/8=320`。顶层传入显示管理器的 `EPD_H=1280` 是历史接口中的打包宽度，不代表面板只有 1280 列。

顶层保留的 `EPD_FREQ=12`、`tLEdly=450`、`tLEw=300`、`tLEoff=200` 是旧管理器接口参数。ES120 的 LE/SPH/CKV 由专用 `frame_ctrl_es120mc1.v` 的计数直接生成；这些旧参数不改变当前管脚时序。`tFdly=0`，因此旧 `EPD_FREQ` 参数也不插入额外帧延时。真实时钟以 MMCM 为准。

### 4.3 行、帧坐标：所有区间左闭右开

以下计数从 0 开始，每行横坐标为 0…361，每帧纵坐标为 0…1622。

- CKV 高电平横区间 `[18,282)`，即 `LSL+GDCK_STA` 开始，持续 264 拍。
- 1600 行源数据：纵区间 `[4,1604)`，SPH 低电平横区间 `[24,344)`，每行恰好 320 个采样。
- 1600 次 LE：纵区间 `[5,1605)`，高电平横区间 `[0,14)`。
- **数据先移入，下一行 LE 锁存**。数据行与 LE 行相差一行是正确流水关系，不是要被“修复”的错位。
- SPV 从第 0 行横坐标 278 拉低，到第 1 行横坐标 278 拉高，覆盖 CKV 下降沿再上升沿。第 1 行 CKV 上升为第一个起始脉冲，第 5 行对应 Gout1。
- DDR 预取请求纵区间 `[2,1602)`，横坐标 23，每帧正好 1600 个请求，比对应源数据行提前两行。
- 数据窗口外输出 `00`，不对像素施加黑/白转换码。

### 4.4 电气时序核对与边界

- datasheet：SDCK 周期至少 16.67 ns；当前 68.076923 ns。
- SDD 建立/保持时间至少 8 ns。输出约束针对实际转发 SDCK，而不是虚设独立的输出时钟；最终需查看该次布线的 `panel_setup.rpt`、`panel_hold.rpt`。
- SPH 建立要求 0.5…0.8 T，保持至少 0.5 T；RTL 采用下降沿更新，名义值 0.5 T。PCB 偏斜和模拟边沿仍应由示波器确认，不能仅用 RTL 仿真证明。
- LE 高宽至少 300 ns；当前约 953 ns。末数据采样到下一行 LE 约 18.5 T，超过 10.5 T 的最小间隔；LE 结束到后续数据窗口也留有 10 T 空白。
- CKV 频率上限 200 kHz；当前约 40.578 kHz，高约 17.972 us、低约 6.672 us，均超过 500 ns 最小宽度。
- SPV 的 100 ns 建立/保持要求通过其对 CKV 的跨行定位留出余量；不能把 SPV 随意移到第 0 行开头。
- VCOM 配置值为 1600 mV 幅值，写 TPS65185 的负 VCOM 设置。保留用户验证值，不从屏幕型号推测修改。电源轨、电平及真实 VCOM 需要实测，不由数字时序报告担保。

## 5. LUT、初始化与本次额外刷白

### 5.1 当前黑白 DU

当前 `frame_processor.DIRECT_MONO=2`，输入为 8-bit 灰度，最高位作二值阈值：0…127 为黑，128…255 为白。

| 旧像素 | 新像素 | 每个阶段的 2-bit 码 |
|---|---|---|
| 黑 | 黑 | 00 |
| 黑 | 白 | 10 |
| 白 | 黑 | 01 |
| 白 | 白 | 00 |

以上关系重复 5 个扫描阶段。`tests/check_epdiy_reference.py` 对照本地 C 的 `epd_wp_epdiy_ED047TC1_1_0_data[5][16][4]`，检查了 5×4=20 个黑白转换项。未声称移植了完整 GC16、温度自适应或全部灰阶波形。

C 波形索引是 `[阶段][新灰阶][旧灰阶打包组]`，每个字节从高位到低位存放四个驱动码。不能反转新/旧图索引，也不能把 `0x00` 当成“刷黑”。

### 5.2 上电序列

```text
ADV 初始化及面板电源就绪
→ 100 ms 等待
→ 初始化两个灰度缓存为白色，复位读写缓冲区指针
→ 10 次白场 + 10 次黑场 + 10 次白场 + 2 次中性扫描
→ 采集并显示黑白竖条，DU 5 次扫描
→ 在竖条实际显示完成后保持 5 秒
→ 若 HDMI 有效：捕获下一完整 HDMI 帧并显示
→ 若 HDMI 无效：缓存重新置白 + 10 次白场 + 2 次中性扫描
→ 捕获并显示一次居中的 NO SIGNAL
→ 静态保持；随后持续检测 HDMI
```

额外白场约 480 ms，不是只送一条行数据或只清 DDR。物理屏刷白后必须把旧灰度缓存也重建为白，否则 DU 会按错误旧图计算，产生漏写。清屏阶段不读取图像 FIFO，不触发图像缓冲区交换。

参考 `render.c:epd_clear_area_cycles()` 每轮为黑 10 次、白 10 次、中性 2 次；本项目上电额外前置白 10 次。LCD 后端 `epd_push_pixels_lcd()` 不将 `time` 参数当作毫秒延时使用，不能据此把波形表的数值直接乘系统毫秒计数。

NO SIGNAL 位图保留现有验证结果：单个字符串、5×7 字模、放大倍数 8，显示包围框 424×56，x=1068…1491、y=772…827。竖条宽度 80 像素，全高；不再修改字形或缩放。

## 6. 数据通路与不可破坏的计数

```text
ADV7611 DE/VS/GRAY + pix_clk，或本地文字/条纹源 + 50MHz
→ 统一数据与时钟选择
→ 灰度捕获 FIFO / DDR 新图
→ 新图、旧图同步读取，DU 比较
→ 驱动码写 DDR
→ 逐行预取 FIFO
→ 64→16 bit 序列化
→ 按已验证接线顺序排列 2-bit 像素对
→ 面板
```

| 数据 | 每行字节 | 每行 64-bit 字数 | 一帧字节 |
|---|---:|---:|---:|
| 8-bit 灰度 | 2560 | 320 | 4,096,000 |
| 2-bit 驱动码 | 640 | 80 | 1,024,000 |

每个 64-bit 驱动字必须产生 4 个 16-bit 输出采样；一行必须消费 **80** 个 FIFO 字，不是 79。最后一次 FWFT pop 不能省略，否则逐行累积错位。全帧检查要求：512,000 个有序 16-bit 采样、128,000 次 64-bit pop、1600 次 LE。

数据地址：灰度双缓冲 `0x0F500000` / `0x0F900000`，驱动双缓冲 `0x0FD00000` / `0x0FE00000`，旧纹理缓存 `0x0F100000`。每个灰度缓冲小于 4 MiB，驱动缓冲小于 1 MiB。纹理通路虽不参与当前二值算法，仍需按接口消费，不能令其阻塞流水线。

完整捕获完成必须同时满足灰度写入完成、1600 行转换及驱动写入完成。只有物理 DU 更新完成才交换屏幕已显示的图像地址。拔线中途不显示半帧；先等待在途 DMA 完成，再切回本地时钟、复位图像流水线、刷白并显示状态。

### 7.1 唯一声明的输入模式

| 参数 | 值 |
|---|---:|
| 有效分辨率 | 2560×1600，逐行 |

| 水平前肩 / 同步 / 后肩 | 48 / 32 / 80 |
| 水平总数 | 2720 |
| 垂直前肩 / 同步 / 后肩 | 3 / 6 / 37 |
| 垂直总数 | 1646 |
| HS / VS 极性 | 正 / 正 |
| 计算行频 | 41.150735 kHz |
| 计算帧率 | 25.000447 Hz |
| 产品代码 / 显示名称 | EPD0130 / ES120MC1-25Hz |
| EDID 字节 54、55 | B9、2B，10 kHz 单位的小端时钟 |
| EDID 字节 127 | 5F |
| 扩展块数 | 0 |

清零字节 35…37 的 established timings；38…53 的未用 standard timings 为 `01 01`；范围描述符设为 range-limits-only，不授权 GTF/CVT 生成额外模式。旧版把 36、37 也填成 01，其中字节 36 bit 0 声明了 1280×1024@75Hz，本次删除。

ADV7611 的 TMDS/LLC 上限是 165 MHz。2560×1600 采用本配置在约 112 MHz 内；电脑曾报告的 268.5 MHz 约 60 Hz 模式已超上限。EDID 只是显示器的能力声明，不能保证扩展坞或显卡一定按要求输出；刷新率列表不等于实时芯片锁定状态。

### 7.2 配置、回读和 HPD

本项目使用 8-bit I2C 写地址：IO=98、HDMI=68、EDID RAM=6C、KSV/Repeater=64、TPS65185=D0。不要混同 7-bit 地址。

- ADV 硬件 RESET 拉低 30 ms，释放后再等待配置启动。
- HDMI `6C=A3` 选择手动 HPD，IO `20=70` 拉低 HPD，KSV `74=00` 禁用内部 EDID。
- 写入 128 字节 EDID。每次配置项严格为 40 bit：`{长度3, 设备地址, 8-bit寄存器地址, 数据, 00}`。寄存器地址计算必须收敛到 8 bit，禁止 9-bit 拼接造成串位。
- KSV `74=01` 启用 EDID，HPD 继续低保持 1 秒。
- 在 HPD 仍低时，逐字节回读 0…127 并与同一配置 ROM 比较；检查 KSV `74[0]`、`76[0]` 为 1。
- 校验通过才写 IO `20=F0`，手动高保持 500 ms，再 HDMI `6C=A2` 返回自动模式。
- 校验失败保持手动 HPD 低，不向源公开损坏的 EDID；继续面板设置以保留本地显示。
- ADV 会在启用 EDID 时自动重算 checksum，因此程序写入值及启用后回读值必须一致。
- 旧短校验把 `6C=A2` 错验成 `A4`。保留通用模块对其他屏幕的参数兼容，ES120 显式使用 A2，并改为完整 EDID 检查。

### 7.3 HDMI 到面板确实已连接

`DIAGNOSTIC_LOCAL_ONLY=0`。合格输入通过 BUFGCTRL 选入 HDMI 时钟，灰度、DE、HS、VS 同时选择 HDMI 数据。只在捕获空闲时切换，等待 64 个系统周期后捕获下一个完整 VS 帧。

HDMI 有效条件同时要求：

1. 内部 EDID 已完整核对。
2. ADV HDMI `04[1]` 为 TMDS_PLL_LOCKED。
3. HDMI `51/52` 读成功，TMDS 测量处于 108…115 MHz 窗口。
4. 原始、未经裁剪的每行 DE 正好 2560 像素，正好 1600 个有效行。
5. 独立 50 MHz 域测得连续两次 VS 间隔在 24…26 Hz 容差范围。VS 停止时自动撤销有效状态。

TMDS 测量公式：`MHz = ((reg51 << 8) | reg52) / 128`，高 9 bit 是整数 MHz，低 7 bit 是小数。每 100 ms 轮询一组 `04/51/52`，NACK 不作为“有信号”。不修改电脑注册表，不强行接受 60/75 Hz 超带宽输入。

### 8.1 新版 ILA 判读
