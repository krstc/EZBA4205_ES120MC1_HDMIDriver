# ES120MC1 逐像素刷新候选版本（2026-09-21）

本版本针对 9 月 20 日 hybrid 版本的横向分区刷新、约 5 FPS、灰雾和拖影反馈。它是待上板验证的候选版本，不是已验证基线；旧 NAND 包和旧源码保留在 `build/hdmi_hybrid_gc16_20260920`，对比度较好的完整 GC16 包保留在 `build/hdmi_native_gc16_20260920`。

## 问题和修改依据

上一版把灰阶恢复拆成 13 个 128 行区域，每个区域独立等待完整 GC16 波形。由此会产生肉眼可见的横向区域依次更新。运动路径也仍然串行等待采集和 DU5 加中性尾帧，不能把面板扫描频率当作新画面的更新率。

本次实际阅读的参考是 [Glider 的低延迟设计说明](https://github.com/Modos-Labs/Glider#low-latency-rendering) 和 [Caster pixel_processing.v](https://github.com/Modos-Labs/Caster/blob/2f714ab7c217e6441c46cfd647764d9a74967aec/rtl/pixel_processing.v)、[Caster caster.v](https://github.com/Modos-Labs/Caster/blob/2f714ab7c217e6441c46cfd647764d9a74967aec/rtl/caster.v)。参考快照在 `datasheet/reference`，Caster 提交为 `2f714ab7c217e6441c46cfd647764d9a74967aec`。

采用其逐像素状态、快刷早期反向取消、静止后统一放行灰阶的思路。没有照搬其他屏幕的驱动时长，也没有启用空间抖动或蓝噪声。灰雾的物理成因和最终改善幅度仍须实测，数字仿真只能验证驱动序列及传输正确性。

## 刷新流程

- 每像素保存 16 bit 状态，区分已完成、二值驱动中和 GC16 驱动中。不能把“新目标已写进 DDR”当成“面板已达到新灰阶”。
- 每次采集产生三个连续面板扫描的数据。正在显示上一包时采集下一帧；只有完整采集、两个 DDR 写通道完成以及上一包显示结束后，才允许复用缓冲区。
- 运动时用阈值二值快刷，采用本地 EPDiy 的完整 DU5 驱动次数。跨输入帧保存剩余次数，不再逐帧重新开始或提前标记完成。
- 黑白端点之间反向时，只抵消已经施加的剂量。例如先刷黑三次，再回到白色，补三次白驱动，而不是重新追加完整五次。中间灰阶出发的 DU 先完成当前方向，避免用线性端点模型误算原生灰阶。
- 连续 20 个输入帧没有像素目标变化后，统一允许尚未到达目标的像素进入原生 GC16。没有横向区域游走。GC16 使用固定的源灰阶和目标灰阶，执行过程中 HDMI 再变化也不会中断这套波形。
- GC16 完成后，不变像素输出 `00`，不定时启动全屏黑白巨刷。M18 仍触发人工刷白和状态重建。
- HDMI 接入提示：完整显示 `HDMI IN`，保持 2 秒，刷白并重建白色状态，完整显示 TMDS/帧率文字，保持 2 秒，再刷白并进入视频。计时从文字波形完成后开始。
- 保留开机三轮白、黑、白清屏，每轮总时间至少 3 秒；不开机显示竖条。提示字仍为原生浅灰色。

## 速率与画质边界

HDMI EDID、接收芯片配置、引脚、SDCK、行场时序、数据串行器均保留上一版内容。

| 项目 | 配置 |
|---|---|
| 输入分辨率 | 2560 × 1600 |
| HDMI 像素时钟 | 111.93 MHz |
| HDMI 总时序 | 2720 × 1646，约 25.00045 Hz |
| SDCK | 50 MHz × 13 / 14.75 = 44.0677966 MHz |
| 面板行、场长度 | 362 个 SDCK × 1623 行 |
| 完整面板扫描 | 约 75.00570 Hz |
| 每包扫描次数 | 3，理论约 25.00190 包/秒 |
| DU5 完整端点变化 | 5 次扫描，约 66.66 ms 的扫描时间 |
| 原生 GC16 | 30 有效相位 + 2 中性相位，约 426.63 ms 的扫描时间 |
| 静止精修放行 | 20 次无输入变化的采集，25 Hz 时约 0.8 秒 |

25 Hz 是新目标的接收与调度频率，不表示每个像素能在 40 ms 内完成任意原生灰阶变化。连续运动时是无抖动的二值画面，停止后恢复原生灰阶；这与全程 16 灰阶视频不同。保留上一版“中间灰阶向白移动一级”的映射，黑白端点不变。

## DDR 格式

| 缓冲区 | 起始地址 | 有效长度 |
|---|---|---|
| 状态 0 | `0x0D000000` | 8,192,000 bytes |
| 状态 1 | `0x0D800000` | 8,192,000 bytes |
| 三相位数据 0 | `0x0E800000` | 3,072,000 bytes |
| 三相位数据 1 | `0x0EC00000` | 3,072,000 bytes |

每一行依次存三个 2 bit 平面，每平面 640 bytes。面板每行只读 80 个 64 bit 字，避免反复读取每像素 8 bit 的整包。25 Hz 输入、75 Hz 面板下，状态读写各 204.8 MB/s，面板数据读写各 76.8 MB/s，总有效负载约 563.2 MB/s，不含总线开销。PS HP0 为 100 MHz、64 bit，FDMA 前端为 50 MHz、64 bit；读取和写入分别核算。

所有地址均经过与 ARM ELF 的加载/保留区间比较。清屏后将两个状态缓冲区重置为 `16'h01ef`（已完成、上次输入白、实际白）。显示读地址在启动时单独锁存，不能随下一帧完成而改变。

另加入 `fdma_page_guard_es120mc1.v`：原 uiFDMA 只按最多 256 拍拆分，不处理 AXI 的 4KB 地址边界。所有读写请求先按页面拆分，外层逻辑事务保持 busy，全部子请求结束后才提交。行为模型检查每个实际子请求不得跨4KB；这一检查覆盖状态行、清屏和三个扫描平面。

## 验证与限制

- 逐像素仿真覆盖全部 256 种原生灰阶转换、DU5 跨包计数、各剩余计数下的反向，以及 GC16 中途输入改变。
- 2560 × 1600 集成仿真使用实际 XPM FIFO、DDR 带等待的行为模型、实际面板控制器和引脚串行器，检查四个完整输入帧、三个扫描平面、每个输出像素及约 40 ms 的包间隔。HDMI 信号源独立按照 2720 × 1646 总时序连续运行，不会等待 FPGA 发出采集请求才产生下一帧。
- 控制仿真覆盖提示显示完成后计时、两次刷白/状态重建、采集显示重叠、静止门限、M18 与断线退出。
- 顶层测试保留实际接收器轮询、EDID 配置及 HDMI 资格判断，模拟外部 I2C 和视频状态。
- 最终综合和布局布线完成：WNS `+0.232 ns`、WHS `+0.051 ns`，现有约束下时序通过，总线偏斜无违反。LUT 使用 12,197 / 17,600（69.30%），BRAM 31.5 / 60（52.50%）。报告和具体通过日志存放在 `build/hdmi_pixel_stream_20260921`。既有 PS 引脚属性、DSP/BRAM 等工具警告仍保留，不能把约束内时序通过等同于模拟电气质量已经实测。
- 本候选已于 2026-09-21 19:33 通过 JTAG 写入 NAND；未执行回读或 `-verify`，也未测量实际光学对比度、拖影或帧率。烧写日志和镜像校验值见 `build/hdmi_pixel_stream_20260921/nand_release/`。GC16 仍是提供的 EPDiy 工程所用温区表，没有新增温度/VCOM 标定。

## 复现入口

在 `eink` 的上一级目录执行：

```powershell
& eink/build/run_pixel_stream_regression_20260921.ps1
& D:/FPGA_IDE/2026.1/Vivado/bin/vivado.bat -mode batch -source eink/build/build_es120mc1_jtag_diagnostic.tcl -tclargs eink/build/hdmi_pixel_stream_20260921 *> eink/build/hdmi_pixel_stream_20260921/console_release.log
& eink/build/package_pixel_stream_20260921.ps1
```

发布脚本另外要求 `regression_results.csv` 中全部 12 项检查通过，包括接收器、交接、EDID、I2C、字体和量化回归；日志保存在候选版本目录。构建日志必须记录 `write_bitstream Complete!`，bit 必须晚于 RTL，最终时序和总线偏斜检查必须通过。NAND 包为 `nand_release/BOOT.bin`，校验值为同目录的 `package_hashes.csv`。这些命令只生成文件，不连接或烧写设备。
